`ProxyLens.xcodeproj` is generated by XcodeGen from `project.yml` and **committed**, and the pbxproj references files individually. Adding, renaming, or deleting any Swift file under `ProxyLensApp/` or `Tests/` means running `xcodegen generate` and committing the regenerated project, or `quality.sh full`/`ci` fails on the sync check.

Manual HTTPS check once capture is running and the CA is trusted (**Trust HTTPS Certificate…** in the app): `curl -x http://127.0.0.1:9090 https://example.com/`.

## Architecture

Modular monolith, ports and adapters. `ProxyLensCore` declares domain types plus the `Ports/` protocols; `ProxyLensApplication` owns use cases and actors; `ProxyLensCapture`, `ProxyLensPersistence`, and `ProxyLensPlatform` implement the ports; `ProxyLensApp` is the only place that knows about all of them.

**`ProxyLensApp/App/CompositionRoot.swift` is the map.** Everything is constructed there in one initializer — read it first to see which concrete adapter satisfies which port and how they are chained. Storage root is Application Support/ProxyLens, overridable with the `-ProxyLensStorageRoot <path>` launch argument (UI tests rely on this).

### Capture path

`NIOProxyEngine` (SwiftNIO) → `HTTPProxyHandler` per connection → `FlowTransaction` builds the flow → `PersistingFlowEventSink` writes through `GRDBSessionStore`/`FileBodyStore` → forwards to `FlowEventBus` → the view model's `AsyncStream<FlowEvent>`. WebSocket frames run the same shape through `PersistingWebSocketFrameEventSink` and `WebSocketFrameEventBus`. Bodies never travel inside flow models: handlers tee bytes to `BodyStore` and pass a `BodyReference`; the UI resolves it later via `FlowBodyReader`.

### Rules and breakpoints

`RulePlanner` in core is pure and synchronous — matching and action planning are decided there and covered by package tests. The `RuleEngine` actor holds a `MutableRuleSnapshot` (a `Sendable` box); NIO handlers call `currentRules()` on their event loop and never touch the actor. Anything asynchronous a plan implies (file reads for Map Local, pausing) happens outside core: `BreakpointCoordinator` is an actor implementing the `BreakpointGate` port, and the handler awaits it while the UI resolves the pause.

### Traffic console UI

The console is AppKit hosted in SwiftUI (`TrafficConsoleView` is an `NSViewControllerRepresentable`; `AppRootView` is the shell).

- One `@MainActor` `TrafficConsoleViewModel` publishes a single immutable `TrafficConsoleSnapshot` (`@Published private(set) var snapshot`).
- `TrafficConsoleViewController` subscribes once and fans the snapshot out: every child controller (`SourceListViewController`, `FlowTableViewController`, `InspectorViewController`, `TrafficFilterBar`, …) exposes `render(_ snapshot:)` and holds no independent state. New UI belongs in this shape — add fields to the snapshot in `TrafficConsoleModels.swift`, render them, don't let controllers query services.
- The view model does not depend on `ProxyLensApplication` types directly. `TrafficConsoleViewModel.swift` declares narrow `Traffic*`-prefixed protocols (`TrafficCaptureControlling`, `TrafficBodyReading`, `TrafficSessionLoading`, …) and conforms the concrete services to them by extension in the same file. That seam is what lets tests construct the whole console without a proxy or database — keep new dependencies going through it.
- Incoming flow events are coalesced on `eventBatchDelay` (40 ms in production) before a snapshot is published.

## Testing conventions

- Integration tests (`Tests/ProxyLensIntegrationTests`) use `@testable import ProxyLens`, instantiate the real view controllers, and assert on rendered AppKit state. Views are located by **accessibility identifier** through the private `descendant(of:in:matching:)` helper, so identifiers like `inspector.summary.url` or `traffic.pane.inspector` are a test contract — renaming one breaks tests.
- Layout assertions put the controller in a real `NSWindow` at a fixed size and call `layoutSubtreeIfNeeded()` before measuring frames.
- Determinism comes from `eventBatchDelay: .seconds(60)` plus an explicit `viewModel.flushPendingEvents()`, and from the private actor doubles at the bottom of the test file (`RecordingCaptureController`, `FinishedEventSource`, `InlineBodyReader`, `StaticWebSocketFrameLoader`, …). Reuse those rather than adding new fakes.
- Tests must not reach the public internet; capture tests use NIO embedded channels and local fixtures.

## Constraints worth remembering

- Swift 6 with `SWIFT_STRICT_CONCURRENCY: complete`, macOS 14+, Swift tools 6.0.
- Pinned dependencies: SwiftNIO, `swift-nio-ssl` (exact), GRDB.swift (exact), swift-certificates.
- `ProxyLensCore` must not import AppKit, SwiftUI, SwiftNIO, or GRDB; capture/persistence/platform must not import UI; never create a cyclic package dependency.
- NIO handlers must not touch UI or do blocking database, filesystem, or certificate work.
